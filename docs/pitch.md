## Slide 1: The problem

A deploy goes out with several commits; minutes later payments fail. "Which change did it?"
takes humans log-diving, and the usual shortcut, *blame the latest commit*, is wrong most of
the time: **32% top-1** on our benchmark.

## Slide 2: Kaizen

One knowledge graph per repository connects **code -> commits -> deployments -> errors ->
incidents -> fixes**. When a service breaks, Kaizen:

1. detects it from runtime telemetry (onset = first bad window),
2. ranks every change in scope with explainable graph features (deterministic, not the LLM),
3. explains the top suspect with citations to graph evidence,
4. opens a revert PR, verifies it in staging against the failing traffic,
5. merges only after a person approves, and remembers the outcome.

## Slide 3: The graph wins (28 scenario variants, S1-S10)

| | Kaizen (graph) | Keyword search (BM25) | Latest commit |
|---|---|---|---|
| Top-1 root cause | **89%** | 39% | 32% |
| Top-1 on held-out scenarios | **83%** | 44% | 28% |
| Function-level accuracy | **89%** | 11% | 0% |
| Confidently wrong | **0%** | 61% | 68% |

Top-1 95% CI for Kaizen: 75-100% (bootstrap, n=28). Weights were never tuned on the held-out
split.

## Slide 4: Why it works, and where it does not

* Remove the code call-path feature and top-1 drops **89% -> 57%**.
* Memory: a recurring bug is ranked with confidence **0.65 -> 0.78** once the earlier incident
  is in the graph, and the fix PR cites the earlier fix.
* Blast radius of the culprit: precision **0.97**, recall **0.96**.
* When evidence is thin (bug in one service, symptom in another, no stack trace), Kaizen says
  **"ambiguous, here are the top 3"** instead of guessing (culprit in the top 3).

## Slide 5: Fast and safe

* Ranking: **58 ms** median per incident; detection -> persisted hypothesis **p50 194 ms**
  (budget 30 s, LLM excluded).
* Never touches production: revert branches only, verification in the repo's own CI, merge only
  with a recorded approval; read-only LLM tools, redaction, citation validation.
* Security review: 14 findings, 0 critical/high; 2 of 4 mediums fixed (webhook body cap, App
  permission), the other 2 accepted with mitigations (`docs/security.md`).
